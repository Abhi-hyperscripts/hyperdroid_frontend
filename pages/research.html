What it covers

From the data file to the deck.

The unglamorous middle of a research project — the part between receiving the data and having something to present.

Your data file

Upload the file you were sent and work from it, rather than re-typing a questionnaire into somebody's proprietary format first.

Open-end coding

Codeframes you author or have generated, applied to free-text answers as a job you can watch, cancel and export.

Coding new rows

When the next wave lands, code only what arrived against the codeframe you already agreed — instead of starting the whole thing again.

Focus groups

Upload the recording and work from what was said, so the qualitative half is not a separate exercise in a different tool.

Insights & tables

Cross-tabulations and custom tables with insight generated against them, so a table arrives with a reading rather than only numbers.

Ask the data

Put a question to the dataset in ordinary language and get an answer you can trace back to the rows behind it.

Desk research

Secondary research alongside the primary, so the context around a finding is in the same project as the finding.

Validation

Checks on the data before you build on it, because the expensive mistakes in research are made early and found late.

Embeddable

Put a view of a finding into something else — a client portal or a page — without exporting a picture of it every time it changes.

Straight answers

The things people ask on the first call.

01

Can we defend the coding to a client?

That is what it is built for. A coding job runs against an explicit codeframe, keeps an audit log of what it did, and exports — so "how was this coded" is answered with a document rather than a shrug.

02

Do we have to accept a generated codeframe?

No. You can author the codeframe yourself, or have one generated and then edit it. The generated one is a starting point, not a verdict.

03

What happens when the next wave arrives?

Code only the new rows, against the codeframe already agreed. The point of a codeframe is comparability across waves, and re-running everything defeats it.

04

Can we see what a run cost?

Yes — cost is reported per job. Automated coding is charged in tokens whether or not a tool shows you, and a research business needs it on the project rather than discovered at the end of the month.

05

Can a job be stopped?

Yes. Jobs are listed with their status and can be cancelled — useful the moment you realise the codeframe was wrong, which is usually about ninety seconds in.

06

Does it handle qualitative work?

Focus group recordings can be uploaded and worked from, and reports produced against the project — so the qualitative half is not a separate tool and a separate deck.

07

Whose AI keys does it use?

Your tenant's. Keys are held in the platform's key store and used at the moment of the call, which is also why the cost per job is yours to see.
